# FabricNET 双次横向单方向测量：实测与视觉复核（2026-10-21）

## 一、实验设计

- 代码：shibie/validate_fabricnet_horizontal_twice_20261021.py
- 运行：[GitHub Actions 39556565410](https://github.com/leaves899/fabric-vision-recognition/actions/runs/39556565410)，130/130完成。
- 固定源：V0.6.3 内部单方向测量函数 pipeline._run_direction，保持原来的 Steerable + Ridge + Centerline + Dual-path density，没有修改底层纱线检测/滤波算法。
- Pass A：原图固定水平角度0°，只识别横向纱线，结果是物理纬密。
- Pass B：同图精准顺时针90°，交换mm/px标定两轴，使用**同一个**水平角度0°检测函数，结果是物理经密。
- 把Pass B的线条逆旋回原图，以红线显示经向，Pass A以青线显示纬向。没有使用Excel纱线真值选择方向、周期或图像角度。
- FabricNET是单张640×480实物显微照片，不是原生8000×6000真实反射/透射双模态采集。无逐根物理纱线真值，视觉中心线F1无法量化。

## 三、实际打开算法叠线的AB图视觉核验

左右图分别为冻结原版和**真实**新算法输出；无人工修正线条。

- [W120](visual_samples/W120_AB.jpg)：纬密GT=33；旧预测85.840（高估160.12%），新预测32.462（误差1.63%）。蓝/青横线明显由误判的细纹理密集响应变为更接近粗横向纱束的间距，视觉上方向与中心候选更合理，但未完成实体逐线标注验证。
- [W035](visual_samples/W035_AB.jpg)：旧版受到斜向纹理干扰，输出不符合织物真实横纵主要轴的斜线；新版固定双横向测量并映回坐标后避免了该严重角度错误。纬密误差73.13%→7.04%，但经密仍低估约52.30%；不能判定双方向全正确。
- [W067](visual_samples/W067_AB.jpg)：旧经/纬密误差54.99%/92.04%；新21.64%/35.21%。仍见青色响应跟随表层水平条纹、竖向红线与物理纱线的对应关系难以确认，未过物理正确性验收。
- [W095](visual_samples/W095_AB.jpg)：旧纬密误差74.69%，新纬密误差77.24%，依然错误。原版程序状态PASS是错误放行的典型案例；新版LOW_CONFIDENCE也不代表能恢复真实纱距。

## 四、结论

1. **实验确证：在当前FabricNET轴向对齐的130张图片上，按用户提出的双次横向识别合成经纬密度，比现有V0.6.3双向算法的密度MAE和双方向10%误差通过率均有提升。**
2. **没有严格证明增益全部来自横向算法更强。** 同时还固定了输入水平0°、绕开自动方向成对评分，因此需要进一步设置单轴/双轴、固定角/估计角消融，判明增益来源。
3. 相同底层函数内部rotate_keep_size会裁剪矩形ROI；布料轴不够平行图像边界时，水平固定角也会出错。W067、W095等不能靠旋转修复。
4. 新版只完成密度PoC，不能宣称真实单根纱线一一对应正确率。正式工位R/T、5cm标定框和8K图像仍需要单独盲测。
