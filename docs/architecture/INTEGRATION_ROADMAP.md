# V5 与 Fabric Measurement Engine V1.5 衔接路线

## 已验证与待验证的界线

V5 是**可运行的代码基线**，并非十项参数准确率通过验收。冻结 V4 使用 Lab、多尺度特征及两套 LightGBM 分类器生成双族候选轨迹；V5 将图像旋转的参考来源改为人工确认的同一根真实纱线两点。其弱点包括：候选轨迹不等于真实根数、复杂布料跨样本效果未经证明、测宽和自动组织尚未具备可靠结果。

V1.5 是**建设建议**，主张认证相机、同位置反射/透射双图、Camera Profile、Gate 2 / Gate 3、频域/投影/自相关候选、中心线与表观宽度计量、Golden Dataset 与 RK3576 测试。没有证据证明此路线已经解决斜纹纹理误导或优于 V5。

## 兼容原则

1. 业务输出保持十项；增加经纬比/斜纹角/Ne-tex advisory 只能作为额外字段。
2. 输入允许模式 A：普通照片 + 5×5cm 内框标定 + 人工参考线；模式 B（拟研究）：固定工位 + 同位置反射/透射 + Camera Profile。不能无通知地把 A 废弃。
3. 人工两点取向作为方向基线与兜底，自动方向检测必须与人工真实方向对照，不允许直接用 FFT/结构张量纹理主方向取代。
4. V4 冻结算法原文件按 SHA 校验；替代实现新建模块，不直接覆盖。
5. 901×901 ROI 适合 Demo 特定处理链路；未来精测纱宽应另保留足够空间分辨率的原图或高分辨率 Tile，不得把缩小图当做原始物理分辨率。
6. 计量结果应同时有 Gate 2 / Gate 3 质量状态、人工真实纱线证据、原始/校正图和版本化 Measurement JSON。

## 建设顺序

- M0：冻结 V5，版本标记、SHA 校验、既有测试回归（本仓库初始化）。
- M1：建立 Golden Dataset，按布料 ID 分隔开发集/独立验证集；补真实纱段、方向和截线根数标注。
- M2：比较 V5 与 V1.5 候选方向算法（0/90/180/270 度、斜纹干扰、跨布料）；自动方向只能作为可拒判候选。
- M3：物理尺度/多 Strip 的经纬密度 Benchmark，错误周期拒判；不承诺准确率直到验证完成。
- M4：高分辨率局部边缘与表观宽度统计，定义粗细候选等级；同时保留色系与纹理。
- M5：组织候选/斜纹特征与人工确认，十项结果状态统一。
- M6：在 RK3576 4GB + 前端同时运行条件下做实机耗时和内存验证。

## 检验指标

- 人工真值：真实纱线方向、截线根数、组织类别与边缘/粗细（如可获得）。
- 模型/算法：方向角差、经纬密度误差、拒判率、失败原因、证据对应性。
- 健壮性：旋转一致性、不同布料、不同颜色、斜纹/毛羽/竹节。
- 工程：Commit、Profile、依赖版本、测试报告、RK3576 峰值内存和端到端耗时。

**任何结果在独立验证集上取得通过前，都只能表示候选或待确认。**
