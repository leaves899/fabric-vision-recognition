## 3. 代码级缺陷：必须做可复现实验而非只凭印象

`shibie/synthetic_capture_8k.py` 中存在如下核心逻辑：

```python
reflect = 38. + 119.*front_w + 82.*front_f
reflect += np.where(cross & top, 48.*wc, 0.)
reflect += np.where(cross & ~top, 37.*fc, 0.)
absorb = np.clip(.52*wc + .55*fc + .10*cross, 0, .91)
transmission = 210.*(1.-absorb) + 9.*(1.-wc)*(1.-fc)
```

- R采用像素亮度加权相加，没有从纱线3D高度、表面法线、材质、照明方向、阴影或可见遮挡真正生成照片。
- **T公式没有调用`_warp_up`的上/下浮沉拓扑**。平纹与3/1在中心线、纱线厚度相同时可能生成近乎一致的透射图。应通过“同几何、仅更改组织、固定随机种子”的差异测试量化，而不是武断地要求真实T的两种组织一定差异巨大；合理的模型要对R/T组合中的组织信息提供可解释物理证据。
- 存在数学极性翻转：`contrast_polarity == "bright"` 时做`255-transmission`，`mixed`时用空间正弦强行改变透射亮度；这并不自动代表真实背光物理。
- 黑色方格来自纱线交叉区被公式压得过暗，白色/亮色网格多为孔隙及纱线表面，不能简单说整张T图“明暗倒反”，但光学分布高度理想化。
- 纱线按过于规则的光滑带状生成，缺少真实的纤维束、捻度、毛羽、粗细变化、光学散射、阴影、局部失焦与真实材料差异。
- `synthetic_photo_guided_flat_8k.py` 仅用照片抽取颜色统计和高频噪声强度，对旧R图做调色；**T仍是旧模型**，也没有真实纱线表面形态。真实照片里的斜纹外观并未物理地生成到合成图。
- 需要审计`physical_yarn_centerlines`及其他真值是否与真实渲染逐像素对得上；不可以把真实织物宏观纹理贴到合成照片上，却继续把旧实体ID视为完美真值。

## 4. 拍摄与真值约束

1. 工位布料平铺，**本轮`rotation_deg=0`、`fabric_rotation_deg=0`、`perspective=0`**。允许纱线本身天然小弯曲和不规则截面，但不要创造相机图像旋转。
2. 相机采集能力按之前约定：直接渲染原生8000×6000，FOV约100mm×75mm，名义`mm_per_px=0.0125`。不可小图插值放大冒充8K。
3. 标定框与织物同一平面，内部**5cm×5cm**，检测和真值都必须排除标定框壁。
4. R/T为同一区域、同一根实体纱线几何，采用不同的有物理依据的照明/成像模型；不得把R颜色简单倒置当T。
5. 可用平纹、2/1斜纹、3/1斜纹及必要的其他变化织物；不能硬编码真值为3/1，也不能将组织标签提供给检测算法。
6. 物理真值单独存储：每根经/纬纱线唯一ID、连续实体中心曲线、纱线真实宽度、根数、纱距/密度、经纬浮沉关系、几何标定、可见/遮挡关系、随机种子、光照参数与原图哈希。
7. 维持有效纱宽P10≥12px的采集能力检查；注意这里不是算法可以猜测的真实纱线宽度先验。
8. **如果没有同区域实拍透射图，就不能报告“真实T已标定”。** 不要借用只有反射的照片来伪造已验证的T参考。

## 5. 强制执行的研发步骤

### M0：核对数据与冻结基线

- 实际打开GitHub源码与报告；确认原版入口、优化入口及已完成CI输出。
- 检索工作区/项目文件/仓库中的《高质量照片.rar》、已有高清布料照片及标注；优先阅读原始大图，记录照片分辨率、拍摄类型、组织标签真实性、是否R/T配对。若不能解包，记录原因与可用替代来源。
- 从当前实验分支开**单独研发分支**，不直接动`main`、不覆盖V0.6.3；保留旧生成器与旧原图作为baseline。

### M1：旧光照的反证实验

- 控制相同几何、中心线、纱宽、随机种子，只改变织物组织（plain / twill_3_1），输出R和T差分/绝对差统计，明确测试T对组织关系是否不敏感。
- 根据合成器真值分开抽取开阔孔隙、仅经纱、仅纬纱、经纬交叉处的R/T灰度直方图、均值、方差、亮度剖面；真值只能用于**渲染器审计**而非检测推理。
- 产生并保留旧图像的失败证据：规则方块、没有真实表面长浮线、过亮/过暗的交织区域、实拍与合成局部差异。
- 把至少3个预计旧生成器不通过的光学/拓扑测试写成自动化回归，避免“靠调色修复”。

### M2：实现2.5D纱线实体与可解释的双光照

优先采用**计算量可控的高度场 / 纱线截面模型**，不是先做昂贵的全三维光线追踪。

- 每根经纬实体纱线用椭圆/超椭圆截面和独立长向起伏表达；交织上/下顺序生成局部高度及遮挡，3/1形成可解释的长浮纱外观，平纹对应更频繁的浮沉起伏。
- 添加有实体意义的纤维束纹理、捻度/毛羽、纱线宽度和表面色系变化。可从实拍照片提取**统计参数**，但不能直接粘贴照片的斜纹条带来污染实体真值。
- R：从表面高度/法线、照明方向、漫反射及少量镜面反射、遮挡与阴影计算，再映射RGB，模拟相机曝光/PSF/噪声。
- T：依据沿光路的局部纤维覆盖、有效厚度、吸收和散射计算透过率；可用Beer–Lambert光学深度作可解释近似，配合背光场/PSF/曝光。孔隙和纱线之间的光强应有合理关系，但**不要直接使用简单明暗翻转或拍脑袋的空间极性正弦项**。
- R/T共享同一物理实体真值，具有不同光学机制；确保生成模型在相同参数及随机种子下完全可复现。
- 保留8000×6000**分块/流式渲染**以限制内存，记录GitHub runner峰值RSS和时间。性能声明不等于RK3576真机表现。

### M3：先做真实图像视觉验收，再跑识别器

生成至少以下三组**0°、原生8000×6000**：平纹、2/1、3/1。分别保存：

- R全图预览、T全图预览；
- 同一对应部位的原生像素600×600或更大的R/T局部，**不是放大小图**；
- 真实高清R参考、原旧合成R/T、新合成R/T的可看清的局部对照，注明真实参考是R还是T；
- 新渲染的经纬纱线真实ID中心/宽度、上下浮沉、真实遮挡位置覆盖图；
- 各组织R/T光强统计与差异证明，尤其平纹与3/1为何不同（或者为何根据物理机制T接近，而R应不同）。

Work必须**真正打开图像进行视觉审阅**并报告看到了什么：光照是否像真实布料、斜纹是否有实际长浮纱、网格是否仍不自然、交叉处是否合理、物理ID标记有无错位。不能把生成文件就宣称“已完成视觉验收”。

### M4：冻结新图再做原版/优化版公平A/B

- 生成参数、随机种子、图片和物理真值先冻结；检测器运行时不得接触生成真值、真实纱距、浮沉关系、组织标签。
- 使用原版V0.6.3**未经改写的正式入口**和最新实验优化入口，在完全相同R/T原图上运行。
- 统一对照**同一个标定框内部ROI**，计算经/纬单截面中心位置precision/recall/F1（**门限内最大一对一匹配**，不可先做无约束匈牙利匹配再阈值过滤）、实际根数/漏检、经纬纱距、密度绝对误差和相对误差、拒识率；额外检查多个门限（0.20/0.25/0.32/0.40纱距）敏感性。
- 比较角度时说明优化算法使用了已知0°工位入口，不能声称自动角度推理提高。组织分类若优化模块尚未实现则标记**未实现**，不能读取真值后冒充预测结果。
- 若宣称一根真实纱线的跨遮挡连续性，使用严格同ID多截面轨迹评价，并显示错误跨根关联；**单截面中心F1不等于物理纱线实体身份F1**。
- 把最差窗口、错误中心、误把孔隙当纱线、3/1组织识别失败等负面结果与实际算法覆盖图一起公开，不允许只放漂亮的平均分。
- 真实实拍照片如果没有可信物理ID/密度/组织标签，只可做视觉诊断，不可编造“真实照片准确率”。

### M5：代码提交、CI与决定

- 最少保存两个与开发参数不同的固定新种子/材料或组织留出场景；不要看完失败样本调参后继续称其为全新独立留出。
- 补齐自动化：R/T图尺寸、0°工位、5cm框、每根物理ID唯一性、交织浮沉拓扑、R/T与GT坐标同源、物理亮度合理性、组织差异检验、真实旧基线结果不被覆盖。
- 最终保存报告、R/T实际图像或GitHub Actions可下载artifacts、600×600原像素局部、对照拼图、真值叠图、逐图视觉记录、A/B指标JSON与Markdown、运行命令、实际Commit SHA、成功/失败CI链接及内存时间。
- 评估是否满足RK3576（4GB+前端）内存要求；如果未在设备运行，诚实标注“仅GitHub Runner/桌面模拟”。
- 仅在物理模型、真实视觉、真值一致性与算法回归证据充分时**提出**合并方案，本轮默认保持独立分支，不合并main。
